# Учёт проездов через шлагбаум

Камеры (RTSP) → распознавание номера ([fast-alpr](https://github.com/ankandrew/fast-alpr)) → белый список, гостевые пропуска и расписание категорий → открытие шлагбаума → журнал, отчёты и аудит.

## Запуск в Docker (рекомендуется)

Нужен [Docker Desktop](https://www.docker.com/products/docker-desktop/) (Windows) или Docker Engine (Linux).

1. Скопировать `.env.example` в `.env` и вписать адреса камер (RTSP), логины и пароли.
2. Запустить `docker-start.bat` или командой:
   ```bash
   docker compose up -d --build
   ```
3. Открыть http://localhost:8000. При первом входе система предложит **создать администратора**.

| Действие | Файл | Команда |
|---|---|---|
| Запустить / обновить после изменений кода | `docker-start.bat` | `docker compose up -d --build` |
| Остановить | `docker-stop.bat` | `docker compose down` |
| Смотреть лог | `docker-logs.bat` | `docker compose logs -f` |

- Модели распознавания входят в образ: интернет нужен только при сборке.
- База, фото, резервные копии и логи хранятся в папке `data/` рядом с проектом, настройки в `.env`. Пересборка и удаление контейнера их не затрагивают.
- Контейнер перезапускается при сбое и стартует вместе с Docker (`restart: unless-stopped`). Чтобы система поднималась после перезагрузки компьютера, в Docker Desktop включите **Settings → General → Start Docker Desktop when you sign in**.
- Часовой пояс для журнала задаётся в `docker-compose.yml` (`TZ: Asia/Tashkent`).
- Не запускайте одновременно контейнер и службу Windows / `start.bat`: они займут один и тот же порт 8000.

## Запуск без Docker (Windows)

1. Python 3.11.
2. Скопировать `.env.example` в `.env` и вписать адреса камер.
3. Запустить `start.bat`: при первом запуске он сам создаст `.venv` и установит зависимости. Модели распознавания скачиваются автоматически (~13 МБ).
4. Открыть http://localhost:8000.

Папку проекта держите по короткому пути (например, `D:\gate`): при очень длинном пути Windows не загружает библиотеку распознавания.

Как служба Windows (автозапуск, перезапуск при сбое): правой кнопкой по `install_service.bat` → «Запуск от имени администратора». Удаление: `uninstall_service.bat`.

## Пользователи и роли

Вход по логину и паролю. Пароли хранятся только в виде хеша (PBKDF2). После 5 неверных попыток с одного адреса вход блокируется на 2 минуты.

| | Охранник | Администратор |
|---|---|---|
| Монитор, ручное открытие, переподключение и перезагрузка камер | ✓ | ✓ |
| Журнал: проверка и исправление номеров, комментарии, направление | ✓ | ✓ |
| Гостевые пропуска, отчёты | ✓ | ✓ |
| Удаление записей журнала | | ✓ |
| Белый список, категории, настройки, резервные копии | | ✓ |
| Пользователи, аудит | | ✓ |

**Аудит** записывает все действия: входы (в том числе неудачные), ручные открытия шлагбаума, изменения белого списка, категорий, настроек и пользователей, исправления и удаления записей журнала, гостевые пропуска, тревоги.

## Страницы

- **Монитор**: видео со всех камер с кнопками «Переподключить» и «Перезагрузить камеру», карточка последнего проезда, ручное открытие с комментарием, что видят камеры (ширина номера в пикселях).
- **Журнал**: по 100 записей на странице. Номер исправляется прямо в строке (✓), подсказку «похоже на …» можно принять одной кнопкой. Есть комментарии, смена направления, удаление (только админ), фильтры «без номера», «подозрительные», «не проверены», «с комментарием», выгрузка проверенных фото для дообучения OCR.
- **Гости**: разовые и многоразовые пропуска на время (2 часа, до 18:00, сутки…), отзыв пропуска.
- **Отчёты**: по дням, часам, категориям, подозрительные проезды, отказы, визиты (въезд → выезд), кто сейчас на территории, Excel.
- **Белый список**, **Категории** (дни и часы въезда, ночная смена 22:00–06:00), **Настройки** (зона поиска мышкой на кадре, пороги, анти-passback, обслуживание), **Пользователи**, **Аудит**.

## Правила допуска

1. Номер в белом списке, пропуск активен и не истёк, время входит в расписание категории → пропуск. Выезд в любое время, если так настроено у категории.
2. Иначе есть действующий **гостевой пропуск** → пропуск. Разовый пропуск после въезда становится «использован», выезд по нему разрешён.
3. Иначе → отказ с причиной в журнале.
4. **Анти-passback**: если машина уже въехала и не выезжала, повторный въезд помечается «⚠ повторный въезд» (`ANTIPASSBACK=warn`) или запрещается (`deny`). Проверяется, когда направление известно точно: камера в режиме «только въезд» или ручное открытие.
5. `EXIT_OPEN_ALL=true` → на выезд шлагбаум открывается всем.

## Камеры

```
CAMERA1_URL=rtsp://user:pass@IP:554/Streaming/Channels/101   # 101 = основной поток, 102 слишком мал
CAMERA1_NAME=Въезд
CAMERA1_DIRECTION=auto      # auto / entry / exit
CAMERA1_ROI=0.25,0.40,0.65,0.90
CAMERA1_SCALE=1
CAMERA1_HTTP_PORT=80        # веб-порт камеры: перезагрузка и канал событий
CAMERA1_ACUSENSE=1          # слушать события камеры о проезде машин
```

Если одну машину видят две камеры, проезд записывается один раз (в пределах `COOLDOWN_SEC`). Если от камеры 20 секунд нет кадров, поток переподключается автоматически.

Для надёжного распознавания номер в кадре должен быть **не меньше 100–130 px в ширину** и сниматься почти прямо. Обзорные камеры дают 55–60 px, поэтому для работы шлагбаума рекомендуется камера у места остановки.

### Учёт по машине (AcuSense)

Камеры Hikvision с AcuSense сами отличают машину от человека. При `CAMERAx_ACUSENSE=1` система слушает события камеры. Если камера сообщила о проезде машины, а номер за 4 секунды не распознан, в журнал всё равно попадает запись «машина без номера» с фото и подсказкой похожего номера из белого списка. Охранник подтверждает её одной кнопкой.

В веб-интерфейсе камеры нужно включить: **Конфигурация → Событие → Smart-событие → Пересечение линии**, провести линию поперёк проезда у шлагбаума, цель обнаружения **«Транспортное средство»**, включить и сохранить.

## Шлагбаум

`GATE_MODE=none` (только журнал), `hikvision` (реле камеры через ISAPI: `GATE_HIK_*`), `http` (запрос на `GATE_HTTP_URL`).

## Обслуживание и мониторинг

- Каждую ночь в `BACKUP_HOUR` (по умолчанию 3:00) делается **копия базы** (хранятся последние `BACKUP_KEEP`, папка `BACKUP_DIR`, лучше другой диск) и **удаляются фото** старше `SNAP_KEEP_DAYS` дней. Записи журнала остаются. Копию можно сделать и скачать вручную в «Настройках».
- **Тревоги**: камера без видео дольше `CAMERA_ALERT_MIN` минут, свободного места меньше `DISK_MIN_GB` ГБ, ошибка резервной копии. Тревога показывается красной полосой на всех страницах, записывается в аудит и, если заданы `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`, приходит в Telegram.

## Структура папки

```
app/            код: config (настройки), db (база), auth (вход и роли), recognizer (камеры, распознавание,
                события камер), maintenance (копии, очистка, тревоги), gate (шлагбаум), web (сайт)
templates/      страницы сайта
static/app.css  оформление (светлая и тёмная тема, переключается по настройке Windows)
data/           база gate.db, фото snaps/, копии backups/, логи gate.log и service.log
.env            настройки с паролями камер (не передавать посторонним)
.env.example    образец настроек без паролей
Dockerfile, docker-compose.yml, .dockerignore   контейнер
docker-start.bat / docker-stop.bat / docker-logs.bat   управление контейнером
start.bat               ручной запуск без Docker
install_service.bat     установка службы Windows без Docker (от имени администратора)
uninstall_service.bat   удаление службы
```

Для переноса на другой компьютер достаточно папки `data/` и файла `.env`.
