# Учёт проездов через шлагбаум

Камеры (RTSP) → распознавание номера ([fast-alpr](https://github.com/ankandrew/fast-alpr)) → белый список + расписание категорий → открытие шлагбаума → журнал и отчёты.

## Установка

1. Python 3.11 (Windows).
2. Скопировать `.env.example` в `.env` и вписать адреса камер (RTSP), логины и пароли.
3. Запустить `start.bat`: при первом запуске он сам создаст `.venv` и установит зависимости. Модели распознавания скачиваются автоматически (~13 МБ).

## Запуск

- **Вручную:** `start.bat`, затем открыть http://localhost:8000
- **Как служба Windows** (автозапуск, перезапуск при сбое): правой кнопкой по `install_service.bat` → «Запуск от имени администратора». Удаление: `uninstall_service.bat`.

Папку проекта держите по короткому пути (например, `D:\gate`): при очень длинном пути Windows не загружает библиотеку распознавания.

## Страницы

- **Монитор**: видео со всех камер, последние чтения (с шириной номера в пикселях), последние проезды, ручное открытие.
- **Журнал**: въезды и выезды с фото, категорией, причиной отказа. Номер можно исправить прямо в строке и нажать ✓ (или просто ✓, если номер верный). Кнопка «Скачать набор для обучения» выгружает проверенные фото для дообучения fast-plate-ocr.
- **Белый список**: номер, категория, владелец, срок действия, отключение, импорт и экспорт Excel.
- **Категории**: дни недели и часы въезда (поддерживается ночная смена 22:00–06:00), выезд в любое время или по расписанию.
- **Отчёты**: по дням, часам, категориям, отказы, визиты (въезд → выезд), кто сейчас на территории, Excel.
- **Настройки**: зона поиска номера рисуется мышкой на кадре, увеличение зоны, направление камеры, пороги распознавания. Применяются сразу и сохраняются в `.env`.

## Правила допуска

1. Номера нет в белом списке → отказ.
2. Пропуск отключён или истёк → отказ.
3. Есть категория → въезд только в её дни и часы. Выезд в любое время, если у категории стоит «выезд в любое время».
4. Без категории → круглосуточно.
5. `EXIT_OPEN_ALL=true` → на выезд шлагбаум открывается всем (в журнале всё равно отмечается отказ, если он был).

## Камеры в `.env`

```
CAMERA1_URL=rtsp://user:pass@IP:554/Streaming/Channels/101   # 101 = основной поток, 102 слишком мал
CAMERA1_NAME=Въезд
CAMERA1_DIRECTION=auto      # auto / entry / exit
CAMERA1_ROI=0.25,0.40,0.65,0.90
CAMERA1_SCALE=1
CAMERA1_HTTP_PORT=80        # веб-порт камеры, нужен для кнопки «Перезагрузить камеру»
```

На мониторе у каждой камеры есть кнопки «Переподключить» (заново открыть поток) и «Перезагрузить камеру» (команда камере Hikvision через ISAPI). Если от камеры 20 секунд нет кадров, поток переподключается автоматически.

Если одну машину видят две камеры, проезд записывается один раз (в пределах `COOLDOWN_SEC`).

Для надёжного распознавания номер в кадре должен быть **не меньше 100–130 px в ширину** и сниматься почти прямо. Обзорные камеры дают 55–60 px, поэтому для работы шлагбаума рекомендуется отдельная номерная камера с ИК-подсветкой у места остановки.

## Шлагбаум

`GATE_MODE=none` (только журнал), `hikvision` (реле камеры через ISAPI: `GATE_HIK_*`), `http` (запрос на `GATE_HTTP_URL`).

## Структура папки

```
app/            код: config (настройки), db (база), recognizer (камеры и распознавание), gate (шлагбаум), web (сайт)
templates/      страницы сайта
static/app.css  оформление (светлая и тёмная тема, переключается по настройке Windows)
data/           база gate.db, фото проездов snaps/, логи gate.log и service.log
.env            настройки с паролями камер (не передавать посторонним)
.env.example    образец настроек без паролей
start.bat               ручной запуск
install_service.bat     установка службы Windows (от имени администратора)
uninstall_service.bat   удаление службы
```

Для резервной копии достаточно сохранять папку `data/` и файл `.env`.
